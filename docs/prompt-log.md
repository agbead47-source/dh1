# 프롬프트 로그

LLM을 쓴 프롬프트와 수정 과정을 날짜와 함께 기록한다(최종 제출물).

## 2026-11-20

### 1. 첫 구현 (Claude Code)

- 프롬프트: `md 참고해서 만들어줘` (CLAUDE.md를 기준 문서로 지정)
- 결과: CLAUDE.md의 1~8장을 따라 처음부터 끝까지 한 번 도는 버전을 만듦
  - `src/parse.js`, `src/normalize.js`, `src/diff.js`와 Vitest 테스트(가짜 fixtures)
  - `src/reasons.js`(임시 사유 목록), `src/export.js`(Delivery Schedule 엑셀)
  - `index.html`, `src/main.js`, `src/ui/render.js`, `src/styles.css`(검토 화면)
- 수정 과정
  - fixtures 통계 테스트의 기대값(고객 기준 행 수)을 잘못 세어 테스트 쪽을 고침. 코드는 그대로
- 문서에 없어서 구현하며 정한 것(기업 확인 또는 팀 합의 필요)
  - 줄 수와 총수량이 같고 날짜도 같은데 날짜별 수량 배분만 바뀐 경우: `date`로 분류
  - 엑셀의 노란색 강조는 줄 단위: 이전에 같은 날짜, 같은 수량의 줄이 있으면 변경된 주문 안에서도 강조하지 않음
  - REMARKS의 수량 표기: 한 줄짜리 주문은 `Previous QTY 5,000`, 여러 줄이면 `Previous total QTY 5,000`. 사유와는 ` / `로 이음
  - `gone`에서 아무것도 고르지 않은 건은 출하 완료와 같이 출력하지 않음(화면에는 사유 미입력으로 셈)
  - 고객사 드롭다운의 기본 선택: 변경 건이 가장 많은 납품처
  - 수주일자가 행마다 다르면 가장 이른 날짜를 씀
  - 화면에 "이전·최신 서로 바꾸기" 버튼과 "가짜 샘플 데이터로 보기" 버튼을 추가(시연, 확인용)

### 2. 대시보드형 화면 개편 (Claude Code)

  - 본문: 요약 카드 4개, 차트 3개, 필터 칩, 변경 목록
  - 차트(라이브러리 없이 CSS 막대): 변경 유형별 건수, 지연이 큰 주문 상위 5건, 고객사별 변경 건수. 패널마다 선택한 고객사 기준인지 전체 기준인지 표시
  - 파일을 올리기 전에도 같은 틀을 보여 주고 할 일 순서를 안내
  - 900px 이하에서는 한 단으로 접고 출력 영역을 목록 아래로 보냄
  - 고친 파일: `index.html`, `src/main.js`, `src/ui/render.js`, `src/styles.css`, `CLAUDE.md` 6장
- 구현하며 정한 것(팀 합의 필요)
  - 유형 차트 막대는 한 가지 색(DH Blue Green)으로 통일. 배지 6색은 색각 구분 검사에서 서로 가까운 쌍이 있어 막대 색으로는 쓰지 않고 이름 라벨로 구분
  - 유형 차트 막대와 고객사 차트 막대를 누르면 각각 필터, 고객사 전환으로 동작
  - 지연 차트는 delayDays가 양수인 건만 상위 5건. 앞당김은 넣지 않음
  - 파일 선택 input을 키보드로도 열 수 있게 바꾸고, 옅은 회색 글자(사유 불필요, 없음)를 DH Gray로 올려 대비를 맞춤

### 3. 실제 자료 대조와 점 규칙 수정 (Claude Code)

- 프롬프트: 실제 전산자료 1개와 Delivery Schedule 3개를 주고 대조 → `그 점있는거 어떻게 구별해` → `점은 지우는게 아니라 구별인데 이거다시읽고 수정해줘`(11/20 커피챗 메모와 제안서를 근거로 지정)
- 처음 구현의 잘못: PO 끝의 점을 "떼어 버릴 것"으로 보고 표준화 단계에서 지운 뒤 그 정보를 버렸음
- 커피챗 메모에서 다시 확인한 내용: 일부 출하된 PO는 전산에서 수정이 안 되어, 남은 잔여 오더를 PO 끝에 점을 찍어 다시 등록한다. 고객에게 보낼 때는 점을 찍을 필요가 없다(고객이 헷갈림)
- 고친 내용: 점을 "잔여 재등록을 구별하는 표시"로 다룸
  - 행마다 전산 등록 PO(`erpPo`)와 점 여부(`dotted`)를 보관, 주문에는 `erpPos`, `dottedRows`, `plainRows`
  - 비교 키와 고객용 엑셀은 점 없는 고객 기준 PO를 그대로 씀(점 찍혀 재등록되어도 고객에게는 같은 주문)
  - 화면 변경 목록에 `잔여 재등록`, `이번에 재등록`, `중복 확인` 표시와 전산 등록 PO를 보여 줌
  - 요약 문구를 `점 제거 N건`에서 `잔여 재등록(점) N건`으로 바꿈
  - 순서: CLAUDE.md 5.1 → 테스트 → 코드
- 구현하며 정한 것(기업 확인 필요)
  - 점 있는 행과 없는 행이 한 주문에 함께 있으면 지금처럼 합산하고 경고만 붙임. 따로 떼어 두 줄로 보여 주지는 않음
  - `이번에 재등록`이어도 사유는 자동으로 채우지 않음

### 4. 전체 UI 손질, Pending Order 표 중심으로 (Claude Code)

- 프롬프트: `전체적으로 UI 수정해줘` → `펜딩오더 쪽을 봐야할거야` → (Shipped Orders/Pending Order는 버튼을 만들까 하는 질문에서) 시트 탭 2개 추가
- 결과: 왼쪽 사이드바 + 오른쪽 본문 구조는 그대로 두고, 본문의 중심을 "변경 건만 모은 목록"에서 "고객에게 나갈 Pending Order 표 그대로"로 바꿈. 비교 규칙과 엑셀 출력 내용은 그대로
  - 사이드바를 작업 순서 3단계(전산자료 올리기 → 변경 검토, 사유 입력 → 엑셀 내려받기)로 묶고 단계마다 상태를 글자와 표시로 보여 줌
  - 정리 결과 요약을 업로드 칸 안으로 옮기고, 읽은 종류(전산자료 / 보냈던 일정표)를 표시. 읽기 오류일 때 칸과 본문 안내를 빨갛게, 다시 고르라는 문구 추가
  - 본문 표: 엑셀과 같은 열 순서와 줄 표시(노란 배경, 초록 배경, 빨간 굵은 EXW). 화면의 표와 엑셀이 같은 `buildExportRows` 결과를 씀. 변경 없는 줄도 "전체" 보기에서 보임
  - REMARKS 칸에서 사유를 고르고, 엑셀에 들어갈 영문 문구를 바로 아래에 보여 줌. 사유 입력은 주문마다 한 줄에만 둠
  - 보기 전환 칩(전체 / 변경만 / 사유 미입력)과 유형 칩, 사유 입력 진행 표시(`사유 3 / 6건 입력`)를 표 위에 붙여 둠. "사유 미입력" 카드를 누르면 미입력만 모아 봄
  - 시트 탭 2개: Pending Order(작업), Shipped Orders(보기 전용). 사라진 주문은 탭 아래 별도 구역에서 "출하 완료 / 주문 취소"를 고름
  - 잔여 재등록 태그를 PO NO. 칸의 펼침 표시로 정리. 뜻이 hover 툴팁에만 있던 것을 눌러서 펼치는 설명으로 바꿈(터치, 키보드 가능)
  - 차트 3개는 "차트로 보기"로 접어 둠
  - 고친 파일: `index.html`, `src/main.js`, `src/ui/render.js`, `src/styles.css`, `CLAUDE.md` 6장
- 수정 과정
  - 처음에는 변경 목록의 행 밀도와 정렬만 다듬다가, "펜딩오더 쪽을 봐야 한다"는 말에 목록을 버리고 표로 다시 만듦
  - 표를 넓게 펼치면 REMARKS 칸이 화면 밖으로 나가서, REMARKS 칸을 오른쪽에 고정하고 열 폭을 줄임
  - 사이드바가 있는 1000px 안팎에서는 표가 거의 가려져, 1100px 이하에서는 한 줄을 카드로 접도록 바꿈
- 구현하며 정한 것(팀 합의 필요)
  - 기본 보기는 "변경만". 변경된 주문의 모든 줄을 보여 줌(그 주문의 변경 없는 줄 포함)
  - 사유 입력 줄은 그 주문에서 변경된 첫 줄, 변경된 줄이 없으면 첫 줄
  - "전체 주문 행" 카드는 엑셀에 나가는 줄 수와 같게 함(주문 취소 줄 포함)
  - 변경 없는 주문의 재등록 태그는 `이번에 재등록`, `중복 확인`일 때만 표시(300줄에서 태그가 너무 많아지지 않게)
  - "사유 미입력" 보기에서 사유를 채운 줄은 바로 사라지지 않고 보기를 바꿀 때 빠짐(입력 포커스 유지와 되돌리기 편의)
  - 입력칸 테두리 색 `#8C8C91`을 새로 정함(흰 배경 대비 3:1 이상). 표의 줄 배경색은 엑셀 출력과 같은 값
  - 화면에서 ETD, ETA, Invoice No., SHIPMENT MODE를 입력받지는 않음(엑셀에서 입력)

### 5. 보냈던 일정표를 이전 파일로 읽기 (Claude Code)

- 프롬프트: `펜딩오더 쪽을 봐야할거야` → `시트 넣으면 출하계획 시트가 없대`
- 원인: 처음 구현은 `출하계획` 시트가 있는 전산자료만 읽었음. 실제 업무는 "전산 다운로드를 직전에 보낸 일정표에 반영"하는 방식이라, 이전 파일로 Delivery Schedule(시트: Shipped Orders, Pending Order)을 올리면 시트가 없다는 오류가 났음
- 고친 내용(순서: 테스트 → 코드 → CLAUDE.md 4장, 7장)
  - `parse.js`: `출하계획`이 없고 `Pending Order`가 있으면 일정표로 읽음(Updated EXW를 출하일로). 둘 다 없을 때의 오류 문구에 두 시트 이름을 모두 적음
  - `normalize.js`: 일정표의 DELIVERY DATE와 REMARKS를 주문에 보관
  - `export.js`: 희망 납기를 같은 주문에 넘겨받고, 변경 없는 줄은 지난 REMARKS를 그대로 둠
  - `diff.js`: 이전 파일이 일정표면 `이번에 재등록`으로 표시하지 않음(일정표에는 점이 없어서)
- 실제 자료로 확인: 일정표 3개와 전산자료 1개가 모두 읽힘. 09.30 → 10.07 일정표끼리 비교하면 납기 변경 74, 신규 20, 사라짐 4, 수량 2
- 구현하며 정한 것(기업 확인 필요)
  - 변경된 줄의 지난 REMARKS는 버리고 이번 사유로 바꿈. 변경 없는 줄만 지난 REMARKS 유지
  - 신규 주문의 DELIVERY DATE는 빈칸(전산자료에 값이 없음)

### 6. Shipped Orders 옮겨 적기 (Claude Code)

- 프롬프트: `시핑오더는 별도로 해야하나?` → `그럼 Shipped Orders/ Pending Order는 버튼을 만들까?`
- 판단: 선적 정보(ETD, ETA, Invoice No., SHIPMENT MODE)는 전산 출하계획에 없어 자동으로 못 채움. 대신 새 자료 없이 되는 부분(시트 넘겨받기, 출하 완료 건 옮겨 적기)만 지금 구현
- 고친 내용(순서: 테스트 → 코드 → CLAUDE.md 7장)
  - `parse.js`: 일정표의 Shipped Orders 시트를 `shipped`로 함께 읽음
  - `normalize.js`: `normalizeShipped`
  - `export.js`: `buildShippedRows`, 워크북에 Shipped Orders 시트 추가(줄이 있을 때만)
- 실제 자료로 확인: 09.30 → 10.07 일정표에서 사라진 4건을 출하 완료로 고르면 4건 모두 실제 10.07본의 Shipped Orders에 있는 주문과 일치. 실제로는 그 사이 Shipped Orders에 새 주문이 6건 생겼고, 나머지 2건은 사라짐으로 잡히지 않는 건(부분 출하로 추정)이라 자동으로 옮기지 못함

### 7. 다운로드를 실제 양식에 맞추고 발송용 설정 추가 (Claude Code)

- 프롬프트: `그럼 다운로드도 바뀌어야 하는거아냐?` → `맞춰줘` → `고객한테 발송용 설정을 해야지 않을까?`
- 처음 구현의 잘못: 납품처별로 파일을 따로 내고, 변경 줄을 노란 배경으로 칠하고, 헤더를 브랜드 색으로 칠했음. 실제 발송본은 납품처 3곳이 한 파일이고 배경색 없이 바뀐 Updated EXW만 빨간 글자였음
- 고친 내용(순서: 테스트 → 코드 → CLAUDE.md 7장)
  - 고객사 선택에 `전체`를 넣어 기본값으로 둠. 전체면 모든 납품처를 한 파일로 냄
  - 발송용 설정: 용도(고객 발송용 / 내부 검토용), DELIVERY DATE 열 포함, Shipped Orders 시트 포함, 파일명에 넣을 이름
  - 고객 발송용 서식을 실제 발송본에 맞춤: 맑은 고딕 11 굵게, 연한 파란 헤더, 실제 열 너비, 신규 줄 `NEW ORDER`
  - 이전의 색 표시(노랑, 초록, 회색)는 내부 검토용에서만 넣음
  - 파일명의 이름은 전산자료의 매출처에서 만듦(`DH-E` → `DHE`). 직접 고칠 수 있음
  - 출하일이 빈 줄은 실제처럼 맨 뒤로 보냄
  - 화면 개편 중 발견된 문제 수정: 주문은 바뀌었는데 남은 줄이 모두 이전과 같으면 사유가 엑셀 어디에도 안 들어가던 것을, 첫 줄에 적도록 고침
- 구현하며 정한 것(기업 확인 필요)
  - 전체 파일 안의 정렬은 출하일, 납품처, PO 순. 실제 파일의 같은 날짜 안 순서는 규칙을 찾지 못함
  - 앞당겨진 EXW도 빨간 글자로 표시함. 실제 발송본에서 빨간 글자는 모두 지연된 줄이었고 앞당긴 예는 없었음
  - 실제 발송본의 QTY 칸 노란 배경(26줄)은 뜻을 몰라 따라 하지 않음
